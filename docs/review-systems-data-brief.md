# GameBuddy 复盘数据方案：请一起确认

本文说明我们准备做的四套系统和每套系统要记录的数据。目的是先对齐范围，再开始采集。请直接在文末问题下补充意见。

TrackMate 等外部上报平台本次不展开，当前数据先保存在玩家本机。

## 1. 我们要解决的问题

GameBuddy 要帮助玩家理解一套卡组如何成型，而不只是统计有没有赢。

围绕这个目标，做四套系统：

1. **原始记录**：把一局里发生的事实按时间存下来。
2. **个人数据**：用最近最多 50 局画五维玩法倾向，并展示最近对局。
3. **单局复盘**：解释这一局的流派如何启动、为何偏离、最终是否成型。
4. **战斗分**：给每一场战斗计算可比较的分数，供后续排行榜使用。

四套系统共用同一份原始记录。个人数据、单局复盘和战斗分都从原始事实重新计算，不把最终分数当成不可追溯的结果保存。

## 2. 四套系统分别做什么

### 2.1 原始记录

这是其他三套系统的数据来源。游戏进行时持续记录，应用中断后可以恢复当前局，结束后归档。

它不直接给玩家展示，也不上传完整对局。

### 2.2 个人数据

桌宠右键打开“个人数据”。页面包含：

- 最近窗口的胜局数。
- 一个主角色。
- 五维玩法倾向：进攻出牌、拿牌克制、精英挑战、商店消费、火堆升级。
- 最近对局列表：角色、是否通关、关底 Boss、最终楼层、最高单回合伤害。

五维图表示“玩家更常这样做”，不是能力评分。至少 3 局才绘制；未知数据不补成 0。

### 2.3 单局复盘

复盘回答一条时间线：

- 这局主要在构筑哪套流派。
- 哪一层、哪张牌让它达到 60 分并启动。
- 分数最高到多少，最终是多少。
- 玩家中途拿防御牌、回血或绕开精英，是不是为了活下去。
- 最接近启动但没有闭合的流派缺什么。

当前流派评分只覆盖铁甲战士。其他角色先展示路线、资源和战斗摘要，不套用铁甲流派分。

60 分代表流派启动，100 分代表接近理想构筑。分数越高，只说明越接近该流派的理想形态。

### 2.4 战斗分

每场普通战、精英战和 Boss 战单独记一条战斗记录，并计算战斗分。

排行榜必须按角色、进阶、游戏版本和敌人组合比较。客户端只保存事实和计算输入；正式排名时由统一公式重算。数据不完整、回放数据和非标准环境不进入排行榜。

战斗分的具体权重尚未确定，本文只确定必须留下的事实。

## 3. 所有系统都要记录的公共信息

每条记录都带：

- `runId`：一局游戏的稳定身份。
- `combatId`：一场战斗的稳定身份；非战斗事件为空。
- 事件序号：用于发现漏记和重复。
- 游戏版本、Mod 版本、协议版本、评分公式版本。
- 角色、进阶等级。
- 发生时的幕数、楼层、时间。
- 数据完整度：每个关键字段标记“已知”或“未知”。

原始 seed 只在本机保存短哈希，不进入可分享记录。

## 4. 原始记录要保存的事实

### 4.1 对局生命周期

- 开局时间、结束时间、游戏时长。
- 结果：胜利、失败、中断。
- 最终幕数、最终楼层、关底 Boss。
- 初始牌组、最终牌组、最终遗物、最终药水。
- 结束时生命、最大生命、金币。

### 4.2 构筑变化

每次牌组发生变化时记录一条：

- 楼层和来源：奖励、商店、火堆、事件、转化。
- 奖励场景下的全部候选牌。
- 实际动作：拿取、跳过、购买、删除、升级、转化。
- 发生变化的卡牌 ID 和升级状态。
- 变化后的完整牌组与遗物。
- 变化前后四个流派的分数、已完成构筑轴、缺失条件。

无法判断玩家到底拿了什么时，记为未知，不猜测。

### 4.3 路线与资源

- 每层房间类型。
- 当前可选路线里是否存在精英。
- 玩家实际进入的房间。
- 进入和离开时的生命、金币。
- 商店每次购买或删牌的价格。
- 火堆动作：升级、回血、其他、未知。

### 4.4 战斗过程

每场战斗记录：

- 普通战、精英或 Boss。
- 敌人 ID 和名称。
- 战前牌组、遗物、药水、生命、最大生命、金币。
- 每张实际打出的牌、升级状态、所属回合。
- 实际造成的伤害及来源。
- 玩家受到的生命伤害、获得和消耗的格挡、治疗量。
- 力量变化、消耗次数、抽牌和生成牌数量。
- 药水使用、能量获得和剩余。
- 回合数、胜负、战后生命。
- 本场最高单回合伤害。

打出的牌和实际伤害是当前最需要补齐的数据。没有它们，就无法验证流派分，也不能公平计算战斗分。

## 5. 各系统使用哪些数据

### 5.1 个人数据

只聚合最近最多 50 局：

- 进攻出牌：攻击牌打出数 / 类型已知的出牌数。
- 拿牌克制：明确跳过数、拿牌数、初始和最终牌组张数。
- 精英挑战：精英战次数、普通战次数、当时是否有精英可选。
- 商店消费：进店次数、已知花费、离店金币、到达幕数。
- 火堆升级：升级次数、回血次数、其他已知火堆动作。
- 最近对局：角色、通关状态、Boss、最终楼层、最高单回合伤害。

每个轴同时保留分子、分母、样本数和未知数。

### 5.2 单局复盘

使用第 4 节里这一局的构筑时间线，并额外产生：

- 四流派最终分、峰值、首次达到 60 分的楼层。
- 每次关键变化带来的分数差。
- 最接近启动但未闭合的流派及缺失轴。
- 连续回血、放弃可选精英、购买防御资源等生存偏离。
- 每场战斗的胜负、掉血、回合数和最高单回合伤害。

复盘文本由这些事实生成。它只描述发生了什么，不把胜负直接解释成流派好坏。

### 5.3 战斗分

一场战斗一条记录，使用：

- 角色、进阶、游戏版本、幕数、楼层、敌人组合、战斗类型。
- 战前生命比例、牌组、遗物、药水。
- 胜负、剩余生命比例、总伤害、总承伤、治疗、格挡。
- 回合数、最高单回合伤害、药水使用数。
- 数据完整度和是否为回放或非标准环境。

排行榜只比较同角色、同进阶、同版本、同敌人组合的完整标准局。

## 6. 明确不记录

- LLM 提示词、模型输出和 API Key。
- 每一帧的完整游戏状态。
- 玩家姓名、设备标识和本地文件路径。
- 可还原对局的原始 seed。

完整牌组和逐回合事实只留在本机复盘记录中。若未来要做跨玩家统计，只上传聚合计数、分数桶和必要的卡牌 ID，不上传整份时间线。

3. 60 分作为“流派启动”的门槛是否同意继续使用？
4. 战斗分第一版是否只比较 Boss 和精英，普通战不进入排行榜？
