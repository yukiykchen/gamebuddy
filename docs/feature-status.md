# GameBuddy 功能实现状态

最后更新：2026-09-08  
项目版本：`0.1.0`  
策略数据目标版本：《杀戮尖塔 2》stable `v0.107.1`

## 状态定义

- **已实现**：代码路径完整，可通过 Replay 数据使用。
- **已实现，待真机验收**：代码已完成，但仍需在安装游戏的 Windows 环境记录端到端结果。
- **部分实现**：已有界面或底层数据，但用户目标尚未完整交付。
- **未实现**：代码中没有可用实现。
- **产品边界**：明确不应实现，避免误解为遗漏。

## 界面显示与实际决策的关系

```text
Bridge 状态
  ├─ 战斗存在 -> 显示真实手牌与敌人；若为 Boss/精英则生成攻略弹窗
  └─ 非战斗
      ├─ 卡牌奖励存在 -> card_reward
      ├─ 休息处事件/房间 -> rest_site
      └─ 有可达地图 -> map_route
```

模型不会直接读取游戏进程，也不会自行猜测可选动作。Agent 先根据协议状态生成候选，再把候选和上下文交给模型复核。

## 验证现状

仓库已经提供以下验证入口：

- `npm run harness:validate-all`：脚本语法、协议、fixture、录制文件和 Mod 文件形状。
- `npm run harness:smoke`：Replay WebSocket 握手和第一份状态。
- `npm run harness:smoke:lifecycle`：战斗、回合、战斗结束和地图事件。
- `npm run harness:inspect -- --once`：真实 Bridge 无界面诊断。
- `docs/windows-validation.md`：真实游戏端到端验收清单。

当前实现不能仅凭 Replay 测试宣称真实 Mod 已完成验收。发布前仍需在 Windows stable `v0.107.1` 至少记录一次：Mod 加载、合法快照、战斗更新、奖励识别、地图路线、休息处、遭遇攻略、断线重连和退出行为。

## 下一阶段建议

优先级从高到低：

1. 完成 Windows stable `v0.107.1` 全链路验收并保留脱敏录制 fixture。
2. 用真实奖励选择与最终结果回测卡牌评分，校准规则权重和置信度。
3. 为 Early Access 版本变更建立知识库差异检查，避免 stable / beta 混用。
4. 扩充遭遇弹窗的实时阶段提示，使建议能结合当前回合和敌方意图。
5. 战斗出牌 Agent 只有在合法行动枚举、能量消耗、目标、随机效果和状态转移均可验证后再启动。
