# 事件选择规则库 TODO

## 目标

事件触发后，GameBuddy 不再推荐地图路线，而是根据当前事件的真实规则、玩家状态和后续风险，给出可解释的选项建议。

Kimi 只负责结合上下文进行取舍，不负责凭记忆猜测 STS2 的事件规则。

## 实施清单

- [ ] 为规则数据记录游戏版本、提取时间和来源，发现版本变化时重新生成。

### 2. 事件规则提取

- [ ] 提取事件类、事件 ID、页面 ID 和每个选项的 `TextKey`。
- [ ] 提取动态变量及其运行时数值，例如金币、生命损失和最大生命损失。
- [ ] 提取选项执行效果：生命、最大生命、金币、卡牌、遗物、药水、诅咒、战斗和后续页面。
- [ ] 提取选项前置条件、锁定状态、致死条件和随机结果范围。
- [ ] 提取选项的 HoverTip 关联内容，用于识别遗物、卡牌、药水和附魔。

### 3. 规则库格式

- [ ] 建立 `event_rules.json` 或等价的版本化数据文件。
- [ ] 每个事件记录标题、页面和选项列表。
- [ ] 每个选项记录确定效果、可能效果、代价、前置条件、风险等级和数据来源。
- [ ] 对无法确认的效果标记 `unknown`，禁止把未知内容写成确定事实。
- [ ] 首批覆盖沉没雕像、沉没宝库、溺亡灯塔、茂密植被等高频和高风险事件。

### 5. 确定性分析器

- [ ] 根据当前生命、最大生命、金币、遗物、药水和卡组评估选项价值。
- [ ] 将生存风险置于普通收益之前。
- [ ] 识别卡组协同、诅咒代价、遗物价值和后续战斗影响。
- [ ] 输出每个选项的结构化利弊、风险和置信度。

### 7. 测试和验收

- [ ] 重新安装 Mod，并确认游戏目录中的 DLL 与构建产物一致。

## 验收标准

完成后，事件建议必须满足：

1. 推荐依据包含可追溯的真实事件效果，而不是只引用按钮文案。
2. 致死、最大生命损失、诅咒和战斗等高风险选项会被明确标记。
3. Kimi 只负责结合玩家状态进行权衡，不能凭空发明事件效果。
4. 无法确认规则时，界面必须明确提示不确定性，而不是给出伪确定答案。
5. 规则库与游戏版本不一致时，系统能识别并降低置信度或停止使用旧规则。
