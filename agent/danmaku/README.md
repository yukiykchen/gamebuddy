# GameBuddy danmaku

人格配置与完整解释见 [PERSONAS.md](./PERSONAS.md)，实际运行配置位于 `language-profile.js`。

## 输出节奏

战斗入场立即启动第一批 AI 评论，此后由桌面端调度器每 15 秒使用最新状态请求一次，每批要求两条不同的角色感想。即使没有新动作也会按周期生成；出牌、怪物行动等事件只更新上下文，不额外触发模型。

弹幕专用模型请求超时为 **60 秒**，两句输出预算为 300 tokens。上一批尚未返回时，下一批正常发起。同一场战斗的晚返回结果仍可排队，普通动作变化不取消请求；新反应可以在队列中优先，但不会强制清掉有效的自由闲谈；高血量/残血评论会在状态改变后失效；换战斗、换角色、换局、断线和死亡会取消旧请求。调度暂停后恢复只启动当前一批，不补发积压周期。其他决策请求仍沿用原本的超时配置。

显示时两条 AI 至少间隔 **6 秒**；已就绪的关键组件通知、技能和精彩时刻优先。场景没有新变化时每批最多接收一句闲聊，接受和显示均至少间隔 **30 秒**。当前目标死亡或消失的评论在返回和播放前都会被过滤；已发生的有效精彩时刻允许历史回顾。

模型结果经过格式与重复过滤，实际可能少于两句；失败、超时或没有新内容时不使用固定闲聊凑数。AI 使用异步流程，不阻塞技能介绍、建议或游戏。

出牌、伤害、生命与格挡都是可选背景；不要求每场/每批提及，更不持续报告“我没血/没防御”。角色可自嘲、调侃、聊兵器或卡牌意象、塔中氛围、旅途和真实回忆，两句没有固定分工。五角色各有13类26条情景例子，每批抽取最多6类参考，禁止固定轮播。

## 角色人格

人格档案位于 `language-profile.js`，实际由 `llm-atmosphere.js` 传入生成请求。以下是产品创作的表达风格，不是官方对白或已证实的背景故事。`voice`另规定每人的句子节奏、用词、笑点逻辑和性格反差。示例只用于控制语感，照抄或近似套用会被过滤，不是轮播词库。

| 角色 | 性格与语感 | 示例 | 避免 |
| --- | --- | --- | --- |
| 铁甲战士 | 硬朗、坚忍、直接，疲惫老兵的冷幽默；关注伤疤、代价与站稳 | 伤口会记住，嘴就不必了。 | 狂喊、无脑莽、鼓励卖血 |
| 静默猎手 | 寡言、冷静、警觉，精确观察与冷讽；关注破绽、动作与耐心 | 动静很大。破绽也是。 | 热血长篇、撒娇、每句毒药梗 |
| 故障机器人 | 理性中带生涩好奇，认真理解情绪，偶尔自我修正 | 我似乎不喜欢这里。这个发现很新。 | 刷错误码、虚构概率、客服腔 |
| 储君 | 矜贵、自负、有戏剧感，危险中仍维护体面；适度使用王权与星辰意象 | 这里的迎宾礼，实在欠缺教养。 | 现代霸总、每句自称朕、虚构随从 |
| 亡灵契约师 | 温柔、从容，以平常口吻谈论死亡和骨头，带诡异黑色幽默 | 别紧张，骨头通常很有耐心。 | 尖叫、邪教狂热、刻意血腥、虚构伙伴动作 |

未知角色使用克制、敏锐的中性观战者。支持五角色英文 ID（忽略大小写）及中文别名。每批两句采用同一角色的人格，但要求不同观察角度与笑点。

## 场景针对性

每批请求包含采样时的回合、玩家生命/格挡/能量、存活怪物名称/生命/格挡/行动，以及最近 45 秒内最多 12 条已接收的 Mod 事件摘要，例如已使用的卡牌、回合开始、召唤/复活/阶段变化。只有 Mod 实际提供、现有事件通路接受的消息才会进入上下文；这里不新增采集协议。模型还收到近期台词以避免重复。

运行时另提供可选的已证实精彩时刻，并保存本局有限的遭遇、残血、恢复、新牌记忆；换局或换角色清空，断线不推断缺失过程。已校验的实时 `card.played` 事实只在同 Mod runId、当前战斗和新鲜时间窗口内转发，不读取历史 Replay 事实作为实时经历。

提示词要求围绕具体怪物或近期事件表达感想，不能编造伤害、胜负、机制或操作建议。快照明确表示请求发起时的局面，晚到的评论不能把旧意图说成此刻尚未执行的动作；未发生的意图不能说成已经命中。

## 怪物技能介绍

技能介绍采用中性色技能框、可见怪物名/行动名；同类多只用原始槽位序号区分。角色感想保留头像和角色名标签。

技能介绍与 AI 评论独立：入场为怪物提供原有技能台词，行动变化时更新；保留悬停中的技能名、类型、效果和来源。行动以 Mod 为准，已有本地 Codex 为悬停补充已知效果。不等待 AI，也不受固定闲聊冷却限制。AI 不可用时这部分照常工作。

技能介绍来源记为 `monster_skill`；固定技能台词属于这一类，不归入 AI，也不混入通用固定闲聊 `original_template`。不同怪物/技能按各自身份去重，保证各自详情可以查看。玩家共享留言继续独立保留。普通推荐只留在原面板/桌宠，不自动转成弹幕；机会通知只播关键卡牌和遗物。

## 重复控制

- AI/普通评论在排队中及输出后 90 秒内按规范化文本去重，忽略标点和空白差异，跨场景保留短期历史。
- 模型返回另做字符二元组近似表达过滤，减少只换几个字的复述；这不是完整的语义去重。
- 最近接受的话题/笑点进入下次请求；血量、防御各120秒最多接受一次，可识别的相同梗90秒内抑制，未必每次都能识别同义变化。
- 每个周期有独立批次身份，同样的场景仍能生成新内容；缓存不会反复播放旧结果。
- 怪物死亡、召唤或暂时空列表不重新触发整场入场。
- 不同有效建议按决策身份区分；技能介绍按场景、怪物与行动身份区分。
- renderer 按消息 ID 幂等创建元素，重复 IPC 投递仅显示一次。

## AI 来源占比

旧代码没有历史上屏统计，不能从配置推断实际百分比。当前主进程记录应用会话内、由 renderer 创建 DOM 后确认的来源：`ai`、`monster_skill`、`original_template`、`recommendation`、`shared`、`other`。这表示渲染，不等于用户已阅读；重启归零，未上屏/已取消内容不计数。

在开发者工具执行 `await window.gamebuddyBridge.getDanmakuStats()`，或查看主进程 `[GameBuddy Danmaku] presentation` 日志：

- `aiPercent`：AI 评论 / 全部已确认弹幕（含技能介绍）。
- `commentaryAiPercent`：AI 评论 /（AI 评论 + 通用固定评论），不含技能介绍、建议和共享留言。
- `bySource`：每类实际计数；无样本时占比为 `null`。

`recommendation` 来源字段仅保留给旧统计/测试兼容；当前推荐不再进入弹幕。每 15 秒请求两句是生成策略，不代表全部弹幕必然达到某个 AI 百分比。

## 验证

`npm run test:danmaku` 覆盖人格选择、周期、慢请求跨批、60 秒超时、场景取消、技能保留、去重和来源计数。`npm run test:danmaku-renderer` 使用隔离数据目录运行实际 Electron renderer/preload，验证重复消息仅创建一个元素及上屏确认。测试使用合成数据和 mock HTTP，不连接真实游戏或付费模型。
