## Context

游戏运行时的 `MerchantRoom.Inventories` 按玩家保存 `MerchantInventory`，其中有卡牌、遗物和药水条目；条目模型已经应用本局升级、折扣和价格修改。GameBuddy 当前快照已有完整牌组、已持有遗物/药水、金币、全地图和 Boss 信息，Spire Codex 上下文还能补齐物品效果与本章精英池。

## Goals / Non-Goals

**Goals:**

- 采集当前界面真实可购买商品和实际价格，不依赖价格范围反推。
- 推荐必须在当前金币内，且只能引用真实库存。
- 同时评价卡牌、遗物、药水、删牌与保留金币。
- 结合完整牌组、全地图、确定 Boss、确定/可能精英及已有物品。
- 进入商店时一次生成完整购物清单，同一次访问中不因逐件购买反复规划。

**Non-Goals:**

- 不执行购买。
- 不模拟随机补货内容。
- 不用伤害或斩杀线计算证明购买收益。
- 不假定“花完金币”一定优于保留预算。

## Decisions

### 1. 商店作为状态快照与显式生命周期共同传输

`GameBuddyState.shop` 保存当前库存，保证中途连接也能恢复；`shop.opened`、`shop.updated`、`shop.closed` 用于精确控制 Agent 和 UI 生命周期。首次读取库存时生成建议；同一次商店访问中的 `shop.updated` 只更新库存与余额展示，不触发新分析。离店后清除锁定清单，下次进店重新计算。

### 2. 运行时字段优先，目录只做效果回退

卡牌直接复用 `CardSnapshot`，保留升级状态、能量/星费和实机描述。遗物与药水发送 ID、名称、稀有度和动态描述。价格只接受 `MerchantEntry` 当前值；无法读取价格的条目保留在诊断快照中，但不进入可购买候选。

### 3. 先评单品，再枚举预算组合

规则层为每件商品计算独立价值与场景：

- 卡牌复用选牌 Agent 的牌组缺口、协同和敌人机制分析，并扣除“买牌而非免费拿牌”的机会成本。
- 遗物按永久收益、触发条件、牌组协同、重复持有与近期强敌适配评分。
- 药水按当前空位、即时保命/爆发/控制能力和近期精英/Boss 距离评分；没有空位时显著降权并提示需先使用或丢弃。
- 删牌优先识别起手打击/防御、诅咒和明显低协同牌，并给出具体删除目标。
- 保留金币根据后续商店距离、当前商品质量和预算余量参与比较。

从可买项中枚举最多三件、总价不超过进店时金币的组合。组合对同类冗余、药水槽位和过度花费施加惩罚。推荐结构直接表达完整购物清单与建议顺序，不要求玩家买一件后再次等待求解。

### 4. LLM 只能复核合法计划

LLM 输入包含完整牌组、遗物/药水效果、金币、地图、确定 Boss、确定/可能精英，以及规则层生成的预算内计划。模型只返回候选索引和理由。非法索引、超预算或请求失败时回退规则首选，不阻断商店建议。

### 5. UI 保持单句结论优先

桌宠默认显示“买「物品 A、物品 B」”“买「物品」并删除「卡牌」”或“先不买，保留金币”。展开后展示完整清单、建议顺序、总花费/余额、主要收益、风险和威胁适配。主面板在商店打开时切到商店视图，列出库存和推荐顺序。

## Risks / Trade-offs

- [Early Access 字段变化] → 对价格和描述使用兼容反射，并保留无法读取字段；协议不接受猜测价格。
- [购买后库存变化] → 保留进店时生成的清单作为本次购物目标，同时刷新实际库存与余额；不对未知补货追加建议。
- [遗物策略缺少逐件人工 Tier] → 以确定效果、牌组协同与遭遇机制评分，并明确置信度；不伪造社区结论。
- [组合数量膨胀] → 当前库存规模小，限制最多三件并保留每类高分项后枚举。
- [药水容量字段缺失] → 容量未知时降低相关判断置信度，不把未知当作有空位。

## Migration Plan

该功能需要重新构建并安装 `GameBuddyBridge`，再更新并重启 GameBuddy。旧 Mod 不会发送商店事件，桌面端会保持现有功能，不会凭地图上的 Shop 节点猜测库存。
