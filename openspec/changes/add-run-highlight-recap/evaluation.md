# 复盘评测与验收计划

日期：2026-10-26。状态：待执行。以下是计划、量表和初始门槛，不是已经测得的效果。

## 1. 评测目标

分别回答：记录是否够用、工具是否查得准、模型是否找到好故事、结论是否有据、玩家是否愿意看。代码测试通过只能证明相应工程行为，不等于趣味或因果解释已经验收。

不使用单一总分掩盖事实错误。事实/失误误判是门槛，趣味、发现率、成本和耗时是独立观察维度。

## 2. 样本集

### 真实对局

首批计划20–30局，覆盖不同角色、套路、普通/精英/Boss、胜利/失败、SL/非SL、长短局和中途采集。数量随可取得样本调整，未覆盖的分组单列，不能冒称全职业有效。

### 精确与干扰样本

1. 升级后死亡，升级实例始终未上手。
2. 升级后死亡，上手但当时资源不足。
3. 牌可用但未打出，不过存在合理取舍，不能直接判错。
4. 有可验证斩杀却结束回合；相邻配对样本加入限伤/目标限制，使同一序列不再可行。
5. 两张同名牌，仅升级其中一张；另一个副本打出。
6. 自动使用、消耗、变形或复制，不能因没有手动打出就说没使用。
7. 药水未使用；配对样本中药水不可用或无法帮助本场。
8. 已有套路核心但未触发；配对样本真实触发且有归因。
9. 10HP/最终9999/扣血10，与只有请求9999的配对。
10. 5段各20，不是单次100；Boss残血收尾与满血/多阶段对照。
11. 获得100格挡、实际吸收12；高格挡与抗伤不混算。
12. 玩家自损、敌人伤害、遗物/持续伤害不被混成某卡输出。
13. 同一战斗SL10次，只保留最终尝试战绩，重载观察重复投递仍只计一次。
14. 重连、跨会话时钟变化、同毫秒多事件、迟到/缺口与截断结果。
15. 中途录制遗漏出牌，模型不能证明整场没用。
16. 长局的精彩片段位于中间或末尾，概览/预算不能只覆盖开头。

合成样本用于准确性与边界；真实对局用于故事性与应用效果，结果分开报告。

## 3. 标注结构

每局由熟悉游戏的人标注：

- 可接受的固定指标真值、完整度及计算口径。
- 多个可接受故事及关键事件/对象，不要求唯一选材或唯一句子。
- 有效的时序/机制联系，哪些只能表述可能性。
- 禁止结论：错误归因、未支持反事实、缺日志造成的假零次。
- 玩家当时可见的信息范围。
- 趣味/反差/转折、套路关联与严重错误类别。

开发集和保留测试集按完整runId分离；同一局、同一战斗的SL尝试及改写版本不能跨集。模型产生的候选不能未经人工复核就充当真值。

## 4. 指标

| 指标 | 定义与评审 |
| --- | --- |
| 固定数字准确率 | 逐项对照独立计算真值；未知错误变0也算错，区分支持与不支持字段 |
| 事实支持率 | 有证据支持的可核实陈述/全部可核实陈述；数值、身份、范围和零次证明分项 |
| 选材有效率 | 选出卡片中，被评审认可有复盘价值的比例 |
| 重要性与正负覆盖 | 三个片段是否抓住本局重要选择/结果，允许失误与高光；不因片段是正向或负向就预设加分或配额 |
| 有价值片段覆盖 | 有限卡位下命中标注片段的情况，按已知重要度观察；不是要求发现所有事件 |
| 连锁联系发现 | 已标注成立联系的命中情况，同时报告虚假联系的误报率 |
| 错误归因率 | 错误宣称卡牌/套路贡献或原因的陈述占比 |
| 失误误判率 | 合理取舍、随机结果或缺证据被定性为玩家错误的比例；配对干扰集重点观察 |
| 证据不足时的处理 | 应降级/放弃的样本是否正确处理，同时监测过度放弃导致漏掉好故事 |
| 趣味与本局特色 | 1–5分：是否有具体反差/转折、是否换一局也能照搬、是否想分享 |
| 结构与多样性 | 固定四项指标的名称/顺序/缺失占位、正常三个重要片段、最后一句总结、渲染后字数、同一片段重复率及不同类型与对象的覆盖 |
| 工具工程质量 | 查询准确、覆盖/分页/截断正确、非法参数处理、预算、缓存、迟到与清空行为 |
| 成本与稳定性 | 总调用数/工具数/输入输出用量/费用（可得时）、p50/p95耗时、成功/回退率、多次运行质量 |

引用ID存在不等于语义成立。check_claims自动结果与语义人工评审分开统计；“模型写得自信”不作为正确标准。

## 5. 趣味量表

- 1分：普通流水账，只说做了什么/剩多少血，缺乏值得讲的关系。
- 2分：有纪录或事件，但泛泛、重复或与本局联系弱。
- 3分：片段具体，有一定反差或实际套路表现。
- 4分：能把前面选择与后面结果串起来，简短、有辨识度。
- 5分：事实准确、转折鲜明，玩家认可“这确实是我这局值得记住的事”。

评审先看支持证据，再独立打趣味分；事实错误不能靠趣味高分抵消。负面结果不自动加分，避免模型为了戏剧性总挑玩家失误。

## 6. 对照实验

A：纯程序固定纪录卡。

B：同一模型、读取紧凑整局日志后直接总结。

C：同一模型、同一事实版本，使用本计划的工具查询与校验Harness。

对同一组样本记录提示/模型/知识/工具版本、预算与输入覆盖；每局可重复运行3次作为初始观察。盲评时随机排列输出，隐藏方案名，报告各维度与差异；20–30局的初步结果不宣称广泛统计结论。

人工至少复核全部严重归因/失误样本及一部分普通片段；争议案例保留分歧与最终处理。LLM评委只辅助批量筛查和成对比较，以人工标注校准，不能完全替代游戏理解。

## 7. 发布门槛与回归

首版建议门槛：

- 固定合成集的受支持数字与身份、有效尝试、SL计数全部正确。
- 负面事实覆盖、未知降级、禁止反事实、预算和清空等硬检查全部通过。
- 已标注严重错误集不出现无依据的玩家失误定性；出现即定位修复，不能以平均分通过。
- 真实集报告事实、趣味、漏选、误归因和费用，不预先虚构90%等效果目标；根据首轮人工对照确定后续门槛。
- 局部行动验证器未完成独立验收时，相应反事实能力保持关闭。

问题案例修复后进入回归集；保留一组未用于调参的能力集。执行现有test:syntax、test:agent、test:review、test:facts、harness:validate-all，并将必要新检查接入现有门禁。UI以实际Electron验证短卡、无过程入口和状态切换。

## 8. 评测产物

每次运行保存：manifest、输入数据修订、样本分组、模型/提示/工具/知识版本、显式工具轨迹、最终输出、自动分项结果、人工评审、用时与用量、失败分类。

评测包可复现检索/计算/校验；冻结响应回放与重新调用模型分开。不同方案输入覆盖或预算不同必须披露。

本计划文档校验通过不等于上述模型效果或Windows采集验证已经完成。
