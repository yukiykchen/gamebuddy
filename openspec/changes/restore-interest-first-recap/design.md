## Context

见 proposal.md。当前流程已经有整局 overview、只读工具、本地关系线索和 0–3 张输出能力，但会把 `localStories` 自动合并到模型结果，并允许模型用结构合法的孤立事实成卡。最近重算因此出现普通选择、普通回血和牵强后果，同时无最终校验也让这些内容直接发布。

目标参考现有长局示例：一句基于所选片段的画像，三张以内互不重复的重点片段，以及只概括这些片段的最后一句总结。这个示例的关键不是固定三张，而是每张都跨越选择与后续结果。

## Goals / Non-Goals

**Goals:**

- 让模型先看整局分布，再抓取少量相关窗口，最后一次性选择 0–3 张。
- 把“有意思”定义成可执行的生成规则，而不是生成后的审批模型。
- 让本地关系帮助检索，不再无条件填充模型未选中的卡位。
- 无好素材时自然留空。

**Non-Goals:**

- 不恢复 `stage=validate`。
- 不要求三个片段，也不要求每局有画像与总结。
- 不放宽数字、名称、对象身份和明确结果的记录来源。
- 不把普通事件包装成性格诊断。

## Decisions

1. **分成发现与成稿两个生成阶段，但不增加成稿后校验。**
   - 调查阶段先读取 overview，至少执行一次与候选有关的窗口抓取后才能提交自由片段。
   - 成稿仍由同一调查会话提交 `candidates`；提交就是最终选择。
   - 只有本地高价值关系且模型不可用时，才走本地 fallback。

2. **候选新增生成期 `interest` 说明。**
   - 每个自由候选同时提交简短的 `interest`：`payoff`、`tradeoff`、`contrast`、`cross_event`、`reversal` 或 `extreme_record`。
   - 这不是第二轮语义裁决；它让模型在生成时明确为什么值得展示，并支持离线评测检查普通背景是否被滥用。
   - `interest` 不展示给玩家。

3. **取消正常模型路径的自动 fallback 合并。**
   - `localLeads` 继续放进 overview，模型可直接选用其已核实关系。
   - 模型提交候选后，只发布它明确选择的候选；不再把 `fallback` 自动追加到三张。
   - LLM 未配置、超时或失败时，保留现有本地高价值关系作为降级展示。

4. **画像和总结只从最终已选片段产生。**
   - 有卡时才生成；没有卡时二者为空。
   - 总结不得加入片段中没有的人物、数字、因果或评价。
   - 画像必须是多个片段支持的本局风格；只有单张片段时允许不显示画像。

5. **最高回合爆发作为整回合聚合指标。**
   - 生成提示和评测明确 `turn_damage` 是玩家回合内 `hpLoss` 总和。
   - 片段要使用这个指标时，可绑定 metric，无需再找一条等于峰值的单次伤害。

## Risks / Trade-offs

- [模型为避免留空而虚报 interest 类型] → 用真实日志 fixture 增加普通事件负例，评测候选是否真的包含两端事实或极端聚合。
- [取消 fallback 合并后卡片变少] → 这是预期行为；空或少卡优于低质量填充。
- [调查调用增加延迟] → overview 保持压缩，窗口限制在候选附近；有高价值 local lead 时可直接读取其证据，不扫描全量日志。
- [本地 fallback 与模型路径质量不一致] → 本地仅保留已有高价值关系类型，不使用普通状态差分。

## Migration Plan

1. 更新提示版本使旧低质量缓存失效。
2. 调整候选合同和正常路径 fallback 合并。
3. 用合成 fixture、真实长局和普通短局验证 0、1、3 张输出。
4. 清理复盘缓存并重算已有对局，人工对照目标样式抽查。
