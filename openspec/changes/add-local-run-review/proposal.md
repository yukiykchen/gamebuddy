## Why

GameBuddy 目前只服务“正在进行的这一局”，玩家离开游戏后看不到自己的角色偏好、构筑习惯和长期变化。需要一个完全本地、可解释的小型复盘系统，把已有流派度与路线/火堆数据沉淀成玩家画像，同时避免把有限数据包装成虚假的能力评分。

## What Changes

- 新增明确的对局生命周期观测：稳定区分开局、胜利、失败和放弃，并提供本地复盘所需的对局标识、角色、难度、楼层和时长。
- 在 Electron `userData` 下保存版本化的最近 100 局摘要；支持断点草稿、原子写入、清空和 JSON 导出，不上传云端。
- 新增“个人数据”独立窗口，直接沿用参考图的完整视觉：黄色街机背景、左侧单一主角色大图、右上蓝青五星雷达、右下统计条和最近游戏记录，不在页面放数据链路或设计说明。
- 桌宠继续常驻，启动时不再创建原有主客户端；玩家右键桌宠或托盘并选择“个人数据”时才按需创建窗口，关闭后销毁窗口以释放 renderer 资源。
- 五星图定义为“玩法倾向”而非能力评级：构筑专注、牌组精简、精英挑战、商店利用、火堆升级；所有轴均使用确定性规则和可追溯原始计数。
- 最近游戏记录固定显示角色、是否通关、关底 Boss、最终楼层和最高单回合伤害；样本不足时明确显示缺失，不调用 LLM 补猜。
- 角色大图优先使用游戏运行时可合法读取的角色素材；不可用时使用 GameBuddy 已有角色桌宠图和文字占位，禁止捆绑参考图中的第三方角色素材。

## Capabilities

### New Capabilities

- `run-lifecycle-observation`: 定义 Mod 与 `gamebuddy.state.v1` 如何可靠发布对局开始、结束、结果及复盘采集字段。
- `local-run-review`: 定义本地历史存储、五星玩法倾向、复盘内容、隐私操作和参考图式 UI。

### Modified Capabilities

（无）

## Impact

- `mod/GameBuddyBridge`：采集稳定对局 ID、结果、难度和生命周期事件。
- `harness/protocol.js`、Replay fixtures：扩展协议与生命周期验证。
- `main.js`、`preload.js`：本地历史仓库、IPC、导出/清空。
- `src/index.html`、`src/renderer.js`、`src/styles.css`：复盘入口、五星图和角色画像页面。
- `agent/knowledge/ironclad-archetypes.js`：仅复用现有确定性流派结果，不改变推荐排序。

## Non-goals

- 不做云同步、账号系统、排行榜或跨设备历史。
- 不把五星图宣称为玩家水平、胜率预测或同社区排名。
- 不在第一版逐回合评判“最优出牌”，不调用 LLM 生成复盘结论。
- 不自动点击、选牌、出牌或修改游戏状态。
