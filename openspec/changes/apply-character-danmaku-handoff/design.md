## 数据与分类

主进程发送弹幕消息时，附加当前 Mod observation 的 `run.character`。弹幕页只用这个字段决定样式，不从弹幕文案猜职业。五个已知角色按交付包的资源名称映射；没有可识别角色时采用不带头像的中性框，避免显示错误职业头像。

只有 `message.recommendation.task === 'card_reward'` 被认定为选牌提示。其余弹幕，包括战斗事实、共享弹幕和其他建议，使用当前职业头像。游戏内自动打击流增量标签是另一套 Mod UI，不在此改动范围内。

## 接入方式

将交付包的 CSS、创建 API 与 PNG 复制到 `src/assets/danmaku-handoff/`。`src/danmaku.html` 先加载交付包，再加载现有弹幕滚动逻辑。现有逻辑调用交付包 `GameBuddyDanmaku.create` 创建主题元素，并继续添加悬停详情、车道位置、滚动和清理行为。

交付包的入场位移动画与现有逐帧滚动会同时修改 `transform`，因此移动中的弹幕不启用该入场动画和悬停位移。保留完整文本显示，不因新样式的省略号策略丢失原有弹幕内容。

用户标出的游戏上方区域约为视口高度的 10.7%–37.8%。弹幕仅使用三条车道，中心分别位于 14%、22%、30%；68px 头像的上下外伸仍位于标注区域内。悬停说明限制高度，并在后两条车道向上展开，避免伸出区域。

## 验证

检查五个职业的主题和头像、选牌提示无头像、未知角色不误用头像，以及原有滚动和悬停详情。运行语法、相关单元测试和 OpenSpec 校验，再在 Electron 弹幕窗口中做视觉检查。
