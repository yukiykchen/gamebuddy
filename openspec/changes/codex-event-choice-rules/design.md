## Context

见 `proposal.md`。仓库的 `agent/data/codex/events.json` 含 66 个事件、56 棵页面决策树和 143 条顶层选项，但 `event_choice` 当前只消费 Bridge 显示文本，规则失败路径固定取第一个按钮。事件数据文件本身没有版本元数据，项目的整体知识基线为 stable `v0.107.1`。

## Goals / Non-Goals

**Goals:**

- 对所有当前可见事件选项形成同一结构的事实、利弊、风险和可执行性分析。
- 多页面事件每次页面变化都重新匹配，不把旧代价用于新页面。
- 新旧 Bridge 均可工作，稳定 ID 提高准确性，文本匹配作为可追溯降级。
- 规则先过滤危险或不可执行项，LLM 只负责局面权衡。

**Non-Goals:**

- 不预测随机奖励的具体卡牌、遗物或药水。
- 不执行事件选项或控制游戏。
- 不把通用启发式包装成逐事件人工攻略。

## Decisions

### 1. 直接索引 Codex 原始事件树，不复制第二份手工规则表

新模块加载 `events.json` 并建立 ID、名称及页面选项索引。事件效果会随 Early Access 更新，重复维护 57 份手工 JSON 容易漂移；原始目录仍是机制事实，评分权重留在代码中并可由 Harness 固定。

### 2. 匹配优先级为稳定 ID、标题、页面选项覆盖

新 Bridge 通过反射尽力读取 `eventId/pageId/optionId`，读取失败返回 `null`，不阻断快照。旧 Bridge 先按规范化标题定位事件，再以可见选项标题和描述选择最吻合页面。只有事件和页面均可靠时标记完整匹配。

### 3. 从显示效果抽取有限的确定事实

解析器只识别生命/最大生命、金币、回血、删牌、升级、降级、变化、附魔、卡牌、遗物、药水、诅咒、战斗和随机性。运行时文本优先于目录文本，因为它包含当前动态数值；目录用于补充页面身份与后续结构。未识别文本进入 `unknown`，而不是猜测。

### 4. 生存门禁先于效用评分

锁定、金币不足和明确致死项标记为不可推荐。其余选项以生命安全、最大生命、删牌/升级、遗物、药水、金币和负面牌作可解释加权；随机性降低置信度。没有可解析事实时不生成规则首选。替代方案是让 LLM 直接读文本，但这无法保证致死门禁，也无法在无 Key 时安全降级。

### 5. Recommendation 携带逐项分析，LLM 只返回真实 eligible 索引

规则结果的 `primary` 与 `alternatives` 均附 `analysis`，顶层携带 `eventKnowledge`。LLM payload 包含同一分析且仅列出允许索引；模型结果不在允许集合时丢弃。UI 直接展示结构化字段，不解析自然语言理由。

### 6. 页面变化继续使用现有事件签名

签名增加稳定 ID、页面 ID、选项 ID 和显示文本。页面推进会产生新签名并重新分析；同一页面重复快照继续去重。事件关闭沿用现有清理逻辑。

## Risks / Trade-offs

- [早期访问版本移动 C# 成员] → 反射读取并允许空值，标题/文本路径保持兼容。
- [中文文本解析遗漏特殊效果] → 未识别部分显式进入 `unknown` 并降低置信度，Harness 覆盖高风险代表事件。
- [数值权重不等于最优策略] → 输出逐项事实和分数构成，模型只能复核，后续可用真实选择结果回测。
- [事件目录缺少独立版本字段] → 推荐和文档使用项目知识基线 `v0.107.1`，后续同步流程必须写入版本清单。

## Migration Plan

先发布兼容新字段的桌面端，再重新构建并安装 Bridge。旧 Bridge 仍可按标题和文本运行；回滚时移除新分析模块并恢复旧字段即可，不改变游戏存档或外部状态。
