## Context

见 `proposal.md`。本地 Spire Codex 快照包含 87 个遭遇，其中 63 个 `Monster`、12 个 `Elite`、12 个 `Boss`。现有攻略任务在入口处过滤普通战，Codex 查询又把非 Boss 一律当成 Elite；桌宠文案也只有 Boss/精英两种。

## Goals / Non-Goals

**Goals:**

- 普通地图战和事件战均能依据实际敌人生成攻略。
- 输出结构与已有 Boss/精英攻略一致，让 UI 无需维护第二套面板。
- 人工社区策略与机制推导策略在数据层和界面上明确区分。
- 快照频繁更新时每场只弹一次。

**Non-Goals:**

- 不逐回合重算攻略或持续弹窗。
- 不基于敌人 HP 推导伤害、斩杀线或出牌顺序。
- 不把搜索结果批量改写成未经审核的逐遭遇档案。

## Decisions

### 1. 遭遇类型增加 `Normal`，目录房间类型映射为 `Monster`

只要 `combat` 非空，先识别 Boss、再识别 Elite，其余归为 Normal。这样问号事件战也能进入攻略链路，并依靠实际敌人匹配，而不是依赖地图节点类型。

### 2. 普通遭遇按实际敌人组合匹配

候选先按 `room_type=Monster` 与当前 Act 过滤，再比较敌人 ID/名称覆盖数和组合大小差异。Codex 的怪物列表可能是生成池，因此“完整匹配”指当前所有可见敌人都包含在同一遭遇的怪物池中，不要求池内每种变体同时上场；找不到完整覆盖时只解释已匹配的实际怪物，不宣称某个遭遇名称。

### 3. 无人工档案时生成机制策略

复用 Codex 的多段、爆发、成长、状态牌、召唤、格挡、人工制品等标签，生成与人工档案同结构的字段。目标优先级结合每只怪的机制标签及当前攻击意图，但不计算伤害。策略增加 `basis=mechanics`、`reviewStatus=mechanic-derived`；已有 Boss/精英档案保持 `basis=community`。

社区搜索显示目前公开资料更完整地覆盖敌人招式和遭遇目录，而非稳定的 63 场逐场人工攻略，因此机制推导比伪造社区共识更可维护。机制目录以 Spire Codex 为准，社区全敌人参考仅作为后续人工复核入口。

### 4. 沿用现有一次性生命周期

签名继续由 Act、楼层、坐标和类型组成。普通战进入后生成一次；关闭后同场状态更新不重开；`combat.ended` 清空签名。

## Risks / Trade-offs

- [共享怪物导致遭遇歧义] → 使用组合覆盖与 Act 共同排序；不完整匹配时退回怪物级标题。
- [机制推导不等于高手经验] → 来源明确标为“机制推导”，不显示社区数量或高可信。
- [事件战没有 Act 对应遭遇] → 仍展示实际敌人的招式、固有机制和通用反制。
- [普通战弹窗频率提高] → 每场仅一次且可关闭，不随回合刷新。

## Migration Plan

这是桌面端和 Agent 改动，不需要修改 Mod 协议。更新并重启 GameBuddy 即可；回滚遭遇类型和桌宠标签映射后恢复仅 Boss/精英弹窗。
