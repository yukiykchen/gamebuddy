## Context

当前 `agent/knowledge/auto-strike.js` 将自动打击规则、卡牌 ID 映射、评分和 UI 数据装饰耦合在一个文件中，只显式覆盖 35 张牌。四路独立审查已按 `cards.json` 实际卡面覆盖全部 87 张铁甲牌；主要发现是现有自动打击 `POISON_WEIGHTS` 把主动误用风险当作持有硬毒，7 项中没有一项具备无条件硬毒证据。

主进程目前会在推荐完成前装饰原始候选，推荐任务完成后又独立计算一次；UI 只读取单个 `archetypeImpact`。现有发往 Mod 的 `draft_impact` 只承载自动打击数据，本变更不扩大该协议。

## Goals / Non-Goals

**Goals:**

- 以一个可审计的 87×4 声明式矩阵作为卡牌归属唯一来源。
- 用共享计算框架实现四套不同闸门与成熟轴，而不是复制四个不一致的评分文件。
- 在原始奖励和推荐完成后使用同一计算结果与 C 型筛选规则。
- 保持流派度、综合选牌分与胜率三者分离。

**Non-Goals:**

- 不预测对局胜率，不更改原有推荐排序。
- 不根据战斗中的出牌时机推断玩家会不会误用主动牌。
- 不扩展 `gamebuddy.state.v1` 或现有 Mod `draft_impact` 消息。
- 不穷举遗物完整卡池；只保留经卡面确认、直接服务四套资源轴的遗物规则。

## Decisions

### 1. 用显式 87×4 矩阵，不用默认中性回退

新增声明式卡牌目录，每个 `color=ironclad` ID 必须包含四个流派键：

```text
cardId -> {
  autoStrike: { role, group, weight, reasonCode, condition? },
  exhaust:    { role, group, weight, reasonCode, condition? },
  strength:   { role, group, weight, reasonCode, condition? },
  block:      { role, group, weight, reasonCode, condition? }
}
```

`role` 限定为 `gate/core/engine/payoff/support/conditional/neutral/softAnti/hardPoison`。`group` 用于同机制共享饱和池，例如力量多段、消耗出口、格挡来源。`condition` 只引用有限的命名条件，不在矩阵里嵌任意函数。

选择显式四键而非“未列出即中性”，因为用户要求每张牌都经过判断，且覆盖测试必须能发现 Codex 新增牌。可复用 `reasonCode` 降低 348 个单元的文案重复。

### 2. 通用评分器 + 每流派轴定义

通用评分器负责：升级有效张数、同组饱和递减、牌组厚度造成的 setup 下降、相关遗物、条件解析、0–100 clamp 和候选前后差。每套定义自己的轴和上限：

| 流派 | 结构轴（初始权重） | 缺轴上限 |
| --- | --- | --- |
| 自动打击 | 地狱狂徒 20、循环 25、完美兑现 15、打击弹药 15、辅助 15、setup 10 | 无狂徒最高 10 |
| 消耗引擎 | 双收益闸门 35、可重复出口 20、批量事件 15、伤害兑现 20、辅助 10 | 无闸门最高 20；单闸门最高 65 |
| 力量叠加 | 力量源 30、多段放大 40、吞吐 15、源/出口平衡 15 | 无可靠力量源最高 20 |
| 格挡壁垒 | 积累/放大闸门 25、格挡转伤 30、格挡来源 30、辅助 15 | 无闸门最高 45；无转化最高 55；两者皆无最高 20 |

权重先由机制而非历史胜率校准。100 分由轴完整性共同达到，不能仅靠总和碰巧 clamp。

### 3. 稀释通过抽取可靠性自然产生

对每套计算前若干抽中“闸门 + 必要轴”的超几何概率。未列入正负角色的牌不获得身份分，但加入后会降低 setup，因此通常产生 0～−2 增量。不同流派使用不同关键集合，避免一张无关牌在四套中机械扣完全相同的固定值。

### 4. “持有影响”与“主动误用”分离

静态 `softAnti/hardPoison` 只用于卡牌进入牌组后就会改变抽取、复制、转换或资源方向的机制。主动打出后才可能误耗核心的牌进入 `conditional`，根据牌组已有条件计算：

- 自动打击：删除现有 `DEMON_FORM/FIEND_FIRE/CORRUPTION/BRAND/HAVOC` 等固定硬毒；`ANGER/CINDER/THRASH/PRIMAL_FORCE` 最多为有卡面依据的软反。
- 消耗：腐化、恶魔之焰、添柴按双闸门和事件收益条件计分，不因误用直接判硬毒。
- 力量：多段攻击只有力量源闸门开启后计完整输出；原始力量为软反而非持有硬毒。
- 格挡：壁垒/坚定不移与全身撞击/势不可当分别计轴；主动清手牌最多条件软反。

`hardPoison` 类型保留给未来确有“持有即破坏”证据的卡；当前 87 张允许该类别为空。

### 5. 统一输出四套分数与四套候选增量

内部结果：

```text
archetypeScores: [{ id, name, score, started, mature }]
archetypeImpacts: [{ id, name, beforeScore, afterScore, deltaPoints,
                     role, reason, explicit }]
```

原始奖励由主进程装饰，推荐结果由 `card-reward` 使用同一纯函数装饰。迁移期间保留旧 `archetypeImpact` 自动打击别名，待现有 renderer/Harness 全部切换后删除内部依赖；发往 Mod 的 `draft_impact` 保持原格式和自动打击语义，避免扩大协议范围。

### 6. C 型 UI 使用确定性筛选

侧栏固定显示四套分数。唯一最高分达到 15 才标记“主流派”；并列最高显示“混合构筑”，全部低于 15 显示“尚未成型”。

候选卡筛选顺序：

1. 排除不可识别和 `deltaPoints=0` 的结果。
2. 显式角色（含软反）优先于纯稀释。
3. 同优先级按 `abs(deltaPoints)` 降序，再按固定流派顺序稳定排序。
4. 最多两条；若只有纯稀释，只展示与当前最高流派相关的一条。

这比固定阈值更稳：小幅但有明确机制的 `+1 弹药` 不会被四条 `−1 稀释` 淹没。

### 7. 完整矩阵文档由同一数据源生成

实现阶段生成 `docs/ironclad-four-archetype-matrix.md`，逐张展示四套角色与原因。测试比较文档记录数、矩阵 ID 与 Codex 87 张 ID，防止代码与说明再次分叉。现有自动打击文档保留为深入说明，但不再作为完整卡池来源。

## Risks / Trade-offs

- **[风险] 348 个评价单元人工维护量大** → 用角色枚举、原因代码、分组和覆盖测试压缩重复，同时生成可审阅文档。
- **[风险] 卡面数据字段存在语义缺口** → 对未确认的结算顺序使用 `conditional` 和保守权重，不把猜测升级为硬毒。
- **[风险] 四套分数初始权重未经历史对局校准** → 明确它是机制完整度；固定模拟牌组做回归，后续可单独校准权重。
- **[风险] 共享牌让多套同时上升** → 这是允许的真实结果；闸门和成熟上限防止辅助牌单独把多套抬高。
- **[风险] UI 信息仍可能偏多** → 侧栏集中四分，候选严格限制两条并优先显式机制。
- **[风险] 旧自动打击消费者依赖单值字段** → 迁移期保留兼容别名和 Mod 消息格式，测试确认无协议回归。

## Migration Plan

1. 建立四流派定义、87×4 矩阵、原因字典和覆盖测试。
2. 引入通用评分器并用固定牌组校准四套闸门、上限、递减和稀释。
3. 将原始奖励与推荐结果迁移到四分/四增量，同时保留旧自动打击兼容别名。
4. 实现侧栏四分和候选最多两条展示，完成 Electron/demo 验证。
5. 生成完整矩阵文档并运行 Agent、Harness、语法测试。

回滚时可恢复旧 `auto-strike.js` 装饰路径；新字段为附加数据，不影响原有推荐决策。
