## Why

当前个人数据把一次真实对局按读档切成多条“中断”，把抵达建筑师后的剧情死亡判为失败，并缺失实际出牌、完整拿牌和准确伤害。必须先建立完整、可核对的本地事实记录，才能让个人数据、复盘和后续评分可信。

## What Changes

- 建立稳定的 `runId` 和 `combatId`：同一对局与同一遭遇在读档后保持身份不变。
- 读档重打覆盖该战斗先前尝试的出牌、回合和结算，只保留最新尝试；读档次数继续单独保存在 Mod 本机目录。
- 补齐文档约定的对局、房间、路线、奖励、商店、火堆、事件、构筑变化、出牌、伤害、格挡、治疗、资源、牌区移动和状态变化事实。
- 在 Electron `userData/facts/v1` 可靠落盘，经事件 ID 去重并记录能力、缺口和未知原因；不上传云端。
- 修正结束语义：当前版本击败第三幕 Boss 并抵达建筑师属于“通关”；个人数据只显示“通关 / 未通关”，活动局不进入最近对局，读档不生成新行。
- 由本地事实重建个人数据摘要；不再用敌人总生命轮询差冒充准确伤害，也不把奖励刷新重复计为新奖励。

## Capabilities

### New Capabilities

- `game-fact-capture`: 定义稳定身份、读档覆盖语义及选择与战斗事实的完整采集契约。
- `local-fact-store`: 定义本地事实落盘、去重、覆盖重打、完整度和恢复行为。
- `personal-run-history`: 定义一局一行、通关/未通关两态及从有效事实生成个人数据的规则。

### Modified Capabilities

（无）

## Impact

- `mod/GameBuddyBridge`：新增经 v0.107.1 核对的 Harmony Hook、身份和事件生产。
- `harness/protocol.js`、observation store、Replay：新增版本化事实信封和验收夹具。
- `main.js`、本地记录模块、`review/service.js`：可靠存储、重打覆盖与摘要重建。
- `add-local-run-review` 中尚未完成的数据采集任务由本变更取代；其纯 UI 任务不受影响。

## Non-goals

- 不自动点击、选牌、出牌或修改游戏状态。
- 不上传完整事实，不建设云端分析、排行榜或账号同步。
- 不在本次确定流派分或战斗分的新公式。
