## Context

当前桌面卡牌分析及 Mod 奖励悬停均使用四流派分数。奖励消息固定四项且只接受铁甲；商店没有通用构筑悬停协议。现有普通推荐和关键弹幕分别运行，必须保持独立。用户本轮已授权完整实现，完成规划后按此授权继续 apply。

## Goals / Non-Goals

覆盖网站五职业全部25套路与明确标注的自动打击补充。完美打击数量增伤属于自动打击中的卡牌作用，不单列体系。只读提示；按最新授权对普通推荐加入共同机制约束，不模拟完整战斗、不推断数量足够。

## Decisions

- 游戏内悬停面板按可见CardNode矩形定位，缺失时使用Hitbox；优先在卡牌正上方留18像素，上方不足时优先右侧、再左侧，再尝试下方，均无空间才限制到屏幕安全区。每帧按实际面板高度跟随卡牌，不再固定在屏幕顶端。

- 组件播报先按真实关系收集全部核心/辅助/遗物，再按体系聚合；按体系＋机会/访问＋对象标记已呈现，避免一牌多体系相互吞掉。每体系文案根据其玩法方向区分，核心、辅助和预算清楚标注，不复述普通推荐。
- 普通遭遇攻略默认只缓存，首次准备完成不自动打开、不挤掉桌宠当前气泡；手动查看入口仍可用。AI悬停在渲染入口强制只采用message.text，旧detail数据不能恢复技术解释。

- 无归属且无已核实机制冲突时systems为空，不再创建generic伪体系。协议保留空项用于完整候选集合校验，UI静默隐藏；AI请求只发送非空项，返回时合并空项，防止模型重建兜底。
- 桌面与Mod统一采用深炭色底、细铜边、柔和阴影与圆角，标题/作用标签共一行，短板与建议对齐排列，多体系有细分隔；警告仅用柔和红色强调。布局按文本实际高度计算，限制面板最大高度并滚动。

- 离线同步网站页面核心/辅助/遗物名单，记录 URL、抓取时间、内容哈希与未匹配 ID。以本地 Codex 牌面补充功能标签；不把同场出现当成核心。
- 使用体系功能组和明确触发条件检查缺失；组件数量原样报告，存在不等于足够。通用抽牌不能独自认定流派。消耗收益、格挡转换等替代分支分别检查，不要求攻略所有核心牌齐全。
- 每条提示有定位、诊断、建议三行。AI 在程序枚举的事实、诊断和建议配对中选择，返回 ID 和严格匹配的文本；任意虚构数量、改变定位或宣称足够都回退。请求按角色、牌组/升级、遗物、候选及上下文签名缓存，异步更新不阻塞悬停。
- 新 card_guidance 消息按奖励/商店当前上下文签名校验，使用独立轻量 codec 与三行面板；关闭、换局、旧结果、售出后立即作废。Mod 支持当前奖励和商店可见卡牌；桌面采用相同数据结构。
- 运行时停止发送 draft_impact 和评分里程碑；旧模块及测试保留兼容研究。关键弹幕改读分类与缺失功能，避免依赖旧分数；保留普通推荐面板。
- 冲突白名单必须有当前路线证据与确切机制原因；非攻略牌不等于冲突，多体系不自动互斥。
- 新增每体系策略手册及共用机制评估：先用明确机制锚点或多组件配合确认路线，再检测候选是否破坏必要对象、事件、资源或重复能力。原始力量的手牌攻击变巨石不等于永久改变整副牌；巨石衍生牌本身不自动作为结构冲突。
- 结构冲突在当前可维持路线的前提下标为不推荐；条件冲突提供牌序或终结用途。原推荐分数只保留其自身排序用途，不新增流派度；规则和模型共用合法候选/计划，并在返回时再次校验。所有牌都不适合且奖励不能跳过时保留风险说明，不能使界面无结果。
- 每个模型请求携带策略、完整已知牌面、机制证据与合法决定范围。AI选择结构化诊断和建议，不允许用漂亮措辞绕过事实或冲突。

## Risks / Trade-offs

实机回归修复：Holder布局矩形不保证覆盖交互牌面，必须用Hitbox与CardNode的可见范围检测悬停，模型绑定与交互节点分离；奖励签名和升级keys直接来自已映射的候选，不再次依赖布局扫描。状态快照增加可选reward（关闭为null），桌面重连优先使用快照恢复，旧Mod缺字段时保留事件兼容。游戏内DLL更新仍需正常重启游戏才能加载。

- 网站命名与本地卡名不同 → 优先图像/来源标识映射，审核别名，报告未解析项。
- AI 超时或臆造 → 规则立即展示，受约束配对验证、60秒截止、迟到结果签名检查及有限缓存。
- 多体系面板过高 → 固定宽度、每条独立三行，滚动容器；不静默裁掉相关体系。
- 游戏程序集位于应用宝转译目录 → 已用 Spotlight 定位 ~/Applications/steam 下的真实安装，完整 Release 编译并安装；实机交互单独说明。
