## Context

见 `proposal.md`。当前「发弹幕」和飞行弹幕在同一个全屏透明 `BrowserWindow` 里。窗口创建时 `setIgnoreMouseEvents(true, { forward: true })`，Windows 上再用 40ms 光标探测和 `elementFromPoint` 决定是否取消穿透。全屏游戏抢前台时，探测坐标经常对不齐，按钮一直保持穿透。

## Goals / Non-Goals

**Goals:**

- 发送按钮所在窗口从显示起就接收鼠标，不经过穿透切换。
- 飞行弹幕层继续穿透，避免挡住游戏操作。
- 输入面板打开时窗口可聚焦，关闭后把焦点交还游戏。

**Non-Goals:**

- 不改弹幕文案、共享提交或 AI 生成。
- 不要求飞行弹幕的悬停详情在全屏下一定可点。

## Decisions

- 2026-10-20用户已确认0.2.9在其环境可用，要求去掉发弹幕周围明显的有色底框。后续修订仅把原生窗口改为transparent:true、backgroundColor:#00000000、hasShadow:false，并把composer页面根背景设为transparent；保留focusable:true和setIgnoreMouseEvents(false)、owner和展开聚焦流程。按钮与输入卡片保留自身半透明深底以保证阅读，周围空白露出游戏。此项取代下文“不透明”要求，不回退独立窗口架构。

- 2026-10-20修订取代先前透明与收起后不可聚焦的设计：发送窗口为普通不透明窗口，创建和收起均保持可聚焦、非穿透。飞行层作为其owner，发送窗保持在其上；光标处于发送窗时飞行层保持穿透，不再循环抬升按钮。只在用户展开时主动聚焦，普通弹幕到来不抢焦点。生产窗口工厂与生命周期移入src下CommonJS模块，让自动验证实际使用同一设置；Mac源码原路径保持。

- 独立composer页面的定位必须以窗口内部空间为界：发送面板放在按钮左侧的124像素处，宽度不再用视口42vw；面板最大宽度360像素，包含内边距。真实Electron回归须验证整个面板矩形落在520×280窗口内，而不止检查hidden属性或脚本语法。

1. 新增一个只放按钮和输入面板的小窗口，跟飞行弹幕层同时显示、同时隐藏。小窗口不调用 `setIgnoreMouseEvents(true)`。
2. 两个窗口仍加载现有弹幕页，用查询参数区分：飞行层隐藏按钮，按钮窗隐藏飞行层。现有 IPC（打开面板、聚焦、提交）继续用。
3. 按钮窗固定在弹幕层所在显示器的右侧垂直居中；面板展开时加大窗口并设为可聚焦，收起后缩回并取消聚焦。
4. Windows 光标探测保留给飞行弹幕悬停，不再作为按钮可点的条件。

备选是继续修探测的 DPI 换算。全屏独占或边框全屏时 `getCursorScreenPoint` 与页面坐标仍可能偏差，所以不采用。

## Risks / Trade-offs

- 原生Windows验收直接运行安装目录的GameBuddy.exe，不以Mac执行ASAR或DOM click代替。测试进程提供本机战斗回放和本机共享接口；通过调试接口只读观察控件矩形、焦点、输入值和状态，鼠标/键盘由Win32 SendInput发出。发送前核对鼠标目标窗口归属测试进程，避免误操作其他应用。测试使用临时用户目录，假密钥和本机服务，不给其他玩家发送测试消息。CI没有可交互桌面时必须失败，不能跳过后报成功。

- [小窗口挡到游戏右侧一条] → 只包住按钮和展开后面板，不铺满屏。
- [两个页面各自注册弹幕监听] → 按钮窗忽略飞行弹幕消息，避免同一句画两次。
