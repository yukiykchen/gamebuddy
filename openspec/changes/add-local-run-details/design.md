## Context

参见proposal.md。现有历史存档保存终局牌组和摘要，事实存储提供有效战斗世代与逐层事件；旧日志缺少伤害角色、实际战斗结果及部分选择对象。复盘已有独立异步渲染。数据库永远只读，本需求完全不访问数据库。

## Goals / Non-Goals

**Goals:** 由纯函数构建详情，使用独立只读IPC、缓存和UI区域，事实可验证，离线可读。

**Non-Goals:** 不复用复盘的故事筛选或推理，不建立新的采集协议，不补造旧日志缺失事实，不访问社区接口。

## Decisions

1. 新增review/run-details.js，将历史元数据和有效事实投影为摘要、分幕路线、集合及楼层履历。选择独立投影而非借用recap模块，避免故事筛选改变历史详情。有效事实由现有factStore提供，投影仍去重相同事件和决策，并合并战斗开始通知。
2. 使用review:getRunDetails只读IPC，验证runId属于历史。renderer独立请求、缓存和替换详情区域；复盘更新只替换自己的区域。原始日志不迁移；字段缺失显示未记录。
3. 独立run-details-ui.js与CSS负责深色详情。分幕路线节点跳至原生details楼层，卡牌按升级与变体分组。集合使用本地catalog中文名称、说明；Spire Codex图标保存到src/assets/run-details并记录来源。卡牌优先使用匹配普通／升级版的中文完整卡面缩略图，缺失时使用肖像插画，再回退通用小卡；保留名称、数量和升级标记。不增加大图悬停或点击放大，不调整事件展示。图片资源在开发期按本地图鉴实体ID同步，运行期完全本地读取；不更新游戏规则或图鉴数值。
4. 逐层资源变化只能来自同层连续状态或显式事实，不把跨续局状态差分当作一次获得或伤害；不把旧combat.ended默认false当作失败。战斗回合数仅在回合编号及角色明确时统计。时长标为记录时长，避免将观测间隔说成游戏内计时。

## Risks / Trade-offs

- [旧局信息不完整] → 保留记录范围说明，未知字段不以零补齐，不以最后遭遇推断死亡。
- [复盘异步更新破坏交互] → 独立兄弟区域局部替换，并验证展开楼层不被重置。
- [图片服务变更] → 仅开发阶段下载静态资源并记录来源，运行期不依赖远程站点。
- [重复或SL事件污染] → 读取有效事实，并对事件、战斗、决策去重；测试重复通知与重新打开场景。

## Migration Plan

无需数据迁移。新模块按需读取现存历史与事实，旧记录可直接打开；回滚代码不影响原始对局文件。实现完成后以独立第二个提交交付。
