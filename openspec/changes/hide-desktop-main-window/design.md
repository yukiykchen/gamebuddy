## Context

当前 Electron 主进程同时创建主面板、悬浮桌宠和弹幕窗口。Bridge 连接、状态存储、Agent 调度与弹幕队列位于主进程，不依赖主面板渲染；但启动流程、应用激活、桌宠菜单、托盘和桌宠点击仍包含创建或显示主面板的入口。

## Goals / Non-Goals

**Goals:**

- 让运行时只显示桌宠和按场景出现的弹幕/建议覆盖层。
- 保持 Bridge、Agent、建议卡、攻略、弹幕、托盘和退出生命周期不变。
- 清理所有能够重新显示主面板的运行时入口。

**Non-Goals:**

- 不删除主面板静态资源或重构共享 IPC。
- 不把主面板中的完整工作台迁移到桌宠。
- 不改变建议计算、Mod 协议或对局记录。

## Decisions

### 1. 停止创建主面板，而不是创建后立即隐藏

启动阶段不调用主面板创建逻辑，应用激活时也不补建窗口。相比“创建后隐藏”，这能避免主面板加载触发额外渲染、推荐刷新和日志订阅，也更符合“关闭显示”的含义。

### 2. 保留 Electron 主进程作为运行宿主

主进程继续负责 Bridge、Agent、桌宠、弹幕和系统托盘。替代方案是删除整个桌面应用，但会同时破坏桌宠和弹幕，因此不采用。

### 3. 暂时保留主面板源码

本次只切断运行时入口，不删除 `src/index.html`、`src/renderer.js` 及关联样式。这样可以缩小变更范围，也便于未来将主面板改造成按需历史复盘页。后续若确认永久废弃，可独立清理死代码和打包资源。

### 4. 主面板专属入口直接移除

桌宠点击、桌宠右键菜单、托盘和应用激活不再触发打开主面板。托盘保留桌宠显隐和退出；不会引入一个无内容的替代窗口。

## Risks / Trade-offs

- [主面板中的完整状态、LLM 日志和手动刷新入口暂时不可用] → 保留源码便于后续改造成按需工具；当前核心建议继续由桌宠承载。
- [主面板专属 IPC 可能成为未使用代码] → 本次只清理明确的打开入口，避免与工作区中其他未提交 UI 修改发生大范围冲突。
- [macOS 点击 Dock 图标后没有新窗口出现] → 这是目标行为；应用继续通过桌宠和托盘提供状态与退出控制。

## Migration Plan

1. 切断主面板启动、激活和用户交互入口。
2. 验证启动后没有主面板，同时桌宠、弹幕、Bridge 和 Agent 正常工作。
3. 若需回滚，恢复启动时创建主面板及相应入口，不涉及数据迁移。
