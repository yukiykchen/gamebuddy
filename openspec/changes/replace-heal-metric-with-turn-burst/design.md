## Context

见 proposal.md。主数字条目前固定取 `battleMetrics` 的累计输出、实际抗伤、累计受伤、实际恢复。峰值已在 `fixedMetrics` 的 `turn_damage` 中算出，标签是「最高回合实际爆发」，并由次级纪录展示。实际恢复要求治疗事件带玩家阵营和明确生命差，这一局因此显示未记录。

## Goals / Non-Goals

**Goals:**

- 第四格改读已有峰值，展示文案为「本回合最高出伤」。
- 次级纪录去掉这一项，避免同一数字出现两次。
- 峰值未知时沿用现有完整性判断，继续显示未记录。

**Non-Goals:**

- 不重算回合伤害，不放宽 `turn_damage` 的完整对局条件。
- 不删除治疗投影，只是主数字条不再展示它。
- 不改总结的生成条件。

## Decisions

1. 展示层换槽，不新做一套峰值。第四格读取 `fixedMetrics` 里 `id === 'turn_damage'` 的 `display`，标签固定为「本回合最高出伤」。这样 0 与未记录仍由现有计算区分。
2. 次级纪录继续过滤「实际抗伤」，并再过滤 `turn_damage`。最高斩杀和 SL 留在原处。
3. 第四格图标由「愈」改为「爆」，未知样式仍看 `display === '未记录'`。
4. `battleMetrics` 的治疗累计保留给既有投影测试，避免这次展示调整改动治疗口径。

备选是把 `BATTLE_METRICS` 第四项直接改成峰值。那样会把治疗从投影结果里拿掉，并让两套指标的完整性条件缠在一起。当前峰值条件已经独立，展示层引用更小。

## Risks / Trade-offs

- [旧复盘缓存仍带「实际恢复」] → 渲染按固定槽位取数，打开时用当前投影，不读缓存里的旧标签。
- [短标签「本回合最高出伤」和数据标签「最高回合实际爆发」不一致] → 只改主数字条文案；数据 id 不变，测试按 id 和展示文案分别断言。

## Migration Plan

改渲染和对应 UI/smoke 断言后，跑复盘展示测试。回退就是把第四格重新绑回实际恢复。
