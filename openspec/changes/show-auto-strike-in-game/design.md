## 数据流

Mod 发布 `card.reward.opened` 时附带当前奖励签名，签名由候选 ID 和升级状态组成。桌面主进程已根据当前卡组与遗物给候选附加 `archetypeImpact`，随后通过同一条本地 WebSocket 发回 `draft_impact` 消息，其中只含签名、候选卡 ID 和百分点增量。沿用现有 JavaScript 评分，避免 C# 与 JS 两套权重漂移。

Mod 的 WebSocket 读循环只解析和校验消息，并把命令入队；Godot 主线程在下一帧读取队列。只有签名与当前奖励完全相同、卡 ID 属于当前候选、增量为有限整数且在合理范围内时才显示。重开或刷新奖励会清空旧标签与旧增量。

## 游戏内呈现

在奖励屏幕上为每个候选创建只读 `PanelContainer`，内含居中 `Label`。三张牌仅按横向坐标排序，提示框固定在用户标注的视口横向 31.5%、49.2%、67.8% 和纵向 35% 位置；悬停卡牌不改变提示框的位置。

提示框使用深棕底色和橙色左边框，与战士无头像弹幕框呼应。非负增量使用绿色文字及上箭头，负增量使用红色文字及下箭头。`PanelContainer` 和 `Label` 均忽略鼠标输入；`FontControlUtils.ApplyLocaleFontSubstitution` 为中文文字提供游戏字体。奖励刷新或关闭时释放整个提示框。

## 验证

先用协议与评分测试检查三张候选、错误签名和刷新；用本地 Windows 版游戏程序集构建 Mod。部署 DLL 后通过真实游戏选牌页检查三张提示框的位置、颜色、箭头和关闭清理。当前游戏正在运行，DLL 必须在安全退出并重新启动游戏后才能加载。
