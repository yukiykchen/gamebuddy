## Context

现有 `director` 仅按事件 ID/触发键去重，recent 文本只写不读；`llm-atmosphere` 90 秒缓存可被不同事件重复投放。adapter 使用楼层和存活敌人名称构造场景，名单改变重置了事件去重。固定台词每怪一条、每动作一条，AI 必须先有固定波次才触发，入场还被排除。基线弹幕测试 28 通过、2 失败（旧入场和带技能名台词断言）。

## Goals / Non-Goals

实现提案中的可观察行为；不引入语义模型去重、额外模型请求、布局改变和角色人格扩展。保留现有台词池用于稀疏回退，保留建议/共享消息的来源与详情。

## Decisions

- 调度器按规范化文本去重排队与最近输出；建议用决策身份隔离，避免不同有效决策的同文案被吞。历史有时间及数量上限，场景切换保留短期文本记录。
- adapter 场景使用明确 combatId（若可用），否则用幕/楼层/坐标与战斗连续性；怪物名单只用于场景说明，不能重建身份。重复死亡切换也幂等。
- 评论触发独立于固定队列。AI 返回结构化状态，区分失败回退与限流/重复的静默跳过；每触发最多一条、避免双发。4 秒调用超时只调整异步弹幕客户端。
- AI 请求携带近期文本作为避重复约束；同事实缓存不反复消费，相同在途请求不复用输出给多个触发；依然由调度器做最终跨来源防重。
- 每次有意义的新评论使旧异步结果失效，另检查场景、generation、accepting 和 closed，防止晚回包污染新局面。不中断游戏/建议。
- 固定回退全局 15 秒间隔，保留首次入场的单条摘要及可用悬停信息，不再为每个敌人各发固定句子。
- renderer 先按消息 ID 去重，再在 DOM 创建后发确认；主进程仅信任当前弹幕窗口，来源取自已调度消息，不信任 renderer 自报来源。会话统计仅在内存与诊断日志中，提供只读 IPC 获取。

## Risks / Trade-offs

- 评论会更少、AI 可能晚几秒出现 → 异步处理，建议依然立即显示，失败稀疏回退。
- 普通状态变化不应使评论失效 → 仅新的评论触发更换异步令牌，生命快照刷新不取消有效请求。
- AI 服务不稳定时无法保证固定百分比 → 报告真实渲染计数，绝不按目标比例编造结果。
- 无明确 combatId 的同层无间断换战斗可能无法识别 → 优先显式 ID，其余遵循实际战斗退出/进入和位置变化，不猜测名单边界。
- 原有未归档 change 的每行动播报要求与本次冲突 → 本次用户要求优先，以新测试和说明记录替代行为，不编辑历史完成任务。

## Migration Plan

仅修改桌面端，无 Mod 协议或数据迁移；重启桌面端后生效。验证使用注入时钟、mock 模型、IPC/DOM 测试和 Electron Replay；不调用真实付费模型或发布版本。
