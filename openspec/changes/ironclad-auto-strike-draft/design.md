## 评分口径

每个候选牌的显示值为 `round(score(deck + card) - score(deck))`，单位是百分点。`score` 是 0–100 的构筑匹配度，不是胜率。评分使用卡牌 ID，名称仅作为兼容路径；升级版可赋予更高的有效张数。

首版结构分采用可调权重：地狱狂徒启动、剑柄打击与劫掠循环、完美打击输出、辅助运转、相关遗物，以及启动与循环同时具备的协同。循环与辅助贡献采用饱和函数，第二张、第三张同名牌的边际贡献递减。首两回合抽到启动牌与循环牌的概率作为小权重稳定性项，随卡组厚度变化。重复地狱狂徒的卡手成本单独扣分。

## 数据与界面

`recommendCardReward` 使用现有 Bridge/Codex 的当前卡组、遗物与候选牌。在选牌结果的每张 `options` 中添加 `archetypeImpact`；只对铁甲战士和可识别候选生成。无数据时不显示百分比，也不猜测。

主面板选牌卡片上方展示“自动打击流 +N% / −N% / 0%”。不新增当前卡组流派度面板；现有首选、理由和跳过行为维持原逻辑。渲染文本必须转义。

奖励事件刚到达时，推荐仍可能在读取资料或等待模型。主进程在发给界面前用同一套纯计算函数为原始候选附上增量，使卡片立即显示；推荐完成后使用推荐对象里的增量。新奖励事件必须清空上一轮推荐，避免旧候选覆盖新候选。

## 验证

用真实卡牌 ID 的固定卡组验证：候选顺序无关、第二张剑柄打击收益小于第一张、第三张小于第二张、地狱狂徒与抽牌牌同在时协同更强、无关牌增量不正、非铁甲战士不显示。验证推荐对象仍满足现有协议。
