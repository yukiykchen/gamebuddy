## Context

见 `proposal.md`。当前 Orchestrator 在签名不变且已有建议时会跳过重算，但 `force: true` 会绕过该检查。主窗口 `did-finish-load` 和 `card.reward.opened` 都会带 `force`。同一次奖励因此会连续发起多次 LLM 请求，每次成功都会 `onRecommendation` 广播，桌宠建议卡跟着换。进行中的同任务请求已经会复用 in-flight promise；缺口是**第一次已经发布之后**的再次 `force`。

## Goals / Non-Goals

**Goals:**

- 同一选牌签名在自动触发路径上只发布一次 recommendation。
- 思考态可以出现；最终建议只出现一次。
- 用现有签名（牌列表 + 可否跳过 + 楼层）识别「还是同一张奖励」。

**Non-Goals:**

- 不改打分公式，不限制模型选 `SKIP`。
- 不为了「看起来更正确」做多次采样再取最后一次。
- 不改事件协议。

## Decisions

### 1. 锁的是「已发布的最终建议」，不是「禁止 SKIP」

玩家要的是只看到最终那一条。第一次合法结果发布后即视为最终结果。自动重入不得覆盖，无论新结果是拿牌还是跳过。

备选：多次请求后取最后一次。否决：界面仍会先闪一条再改；也无法定义何时是最后一次。

### 2. 自动 `force` 不得打穿同签名锁

`consider` 在 `card_reward` 且 `lastSignature` 相同且已有合法建议时，即使 `force: true` 也返回已有建议。窗口重载改为：已有建议则只广播，没有才计算。

`force` 仍用于：尚无建议时打开奖励、玩家点击刷新。刷新通过独立选项（例如 `force: true` 且 `reason: 'refresh'`）允许换一条，且一次刷新只发布一次。

备选：去掉所有 `force`。否决：打开奖励时若签名碰巧与上一层相同，可能需要强制开算；刷新也需要出口。

### 3. 发布前不展示候选选择

保持现有策略：启用 LLM 时等这一次复核结束再广播。失败且没有上一次同奖励建议时，不展示错误选牌。新增约束是：成功发布后不再发第二次。

## Risks / Trade-offs

- [重启桌面端会丢失内存中的建议，会再算一次] → 接受；新进程没有「中间结果」，只会出一条。
- [玩家想在同一张奖励上再问一次] → 用主面板刷新；自动事件不会重问。
- [第一次 LLM 选了玩家不认同的 SKIP] → 这是策略质量问题，不在本次用反复询问来「改到满意」。

## Migration Plan

只改 Orchestrator 与主进程触发条件。回滚这两个文件即可。无需迁移存档。
