# AI 辅助流派知识与验证流程

AI 适合参与。主要价值是整理、提出替代路线、找反例与解释缺口。实时打分由固定版本算法执行。本轮实际使用当前 AI 的推理整理草案，没有调用项目付费模型接口，也没有将本地玩家记录上传第三方。

## 1. 输入包

提供 gameVersion、cards/relics 的 ID 与确切效果、完整牌表、升级与已确认附魔、公开来源、未知字段。未提供的效果必须写 unknown。参考草案和验证牌组分离；给初标者的输入不含当前算法分数，也不以胜负暗示流派。

## 2. 参考构筑整理提示词

```text
你负责为《杀戮尖塔 2》构筑教学整理一条流派路线。仅依据随附指定版本的卡牌、遗物事实和真实牌表，不调用记忆补全效果。

输出：
1. 一套完整参考牌表：稳定 ID、数量、升级；说明哪些来自实战、哪些是你提出的修改。
2. 标志性功能、通用支持功能及合理需求量；每个需求说明牌面证据。
3. 可替代组件：提供相同功能的证据、前置条件与无法替代的部分。
4. 配合关系及成立条件；指出缺少某功能后仍然有效的部分。
5. 至少三个反例：只有通用牌、只有孤立核心、组件齐但牌组被无关牌稀释。
6. 未知效果、版本差异和仍需实战验证的假设。

禁止把攻略全部核心牌列为必需；禁止用稀有度推导功能；禁止把“格挡放大”当成“格挡留存”。
不要给实时分数，不要宣称唯一最优或必胜。所有输出标记 draft，等待独立审核。
```

建议结构：

```json
{
  "status": "draft",
  "gameVersion": "v0.107.1",
  "archetypeId": "block",
  "variantId": "barricade-body-slam",
  "cards": [{"id": "BARRICADE", "count": 1, "upgraded": true}],
  "roles": [{"id": "retention", "need": 1, "evidenceIds": ["BARRICADE"]}],
  "substitutes": [],
  "connections": [{"from": "retention", "to": "generation", "condition": "明确事实"}],
  "sources": [],
  "unknowns": [],
  "reviewedBy": null
}
```

示例结构不是完整牌表。程序需校验 ID 存在、数量合法、效果与版本一致、参考满足自身需求、来源存在、训练／验证 run ID 不重合。AI 自称 reviewed 不算独立审阅。

## 3. 独立初标提示词

```text
请仅根据牌面机制，为这五套牌各自标注主要方向和可接受的副方向。你看不到算法分数。
每套给出 supportingCardIds、关键配合、缺失功能和 ambiguous 标记。
混合构筑允许多个合理方向。不能因为有一张核心就忽视其余牌，也不能根据是否通关改变方向。
若证据不足，标记 unknown，而不是强行分到给定的四类。
```

当前 samples.json 是同一 AI 研究者的预运行初标，尚未形成独立双人标签。五套已用于检查，后续只作为校准集。正式验收需独立玩家复核，并用未参与改权重的新样本检验；不允许通过新增相同牌表为参考来“修复”测试。

## 4. 找反例与辅助解释

把参考和计算分解交给评审，要求指出过度扣分／刷分的构筑，尤其关注消耗压缩、检索、费用、附魔和遗物替代。评审只提出可复现反例，不能直接覆盖分数。

玩家解释仅使用固定计算输出：referenceId、presentRoles、gaps、替代候选及未知项。可以生成“已有 X，缺 Y，因此出现 Z 时值得关注”的自然语言，禁止把契合度变化改写成胜率变化，禁止把候选建议说成已经获得。

## 5. 发布与成本

AI 草案经独立审阅后，保存为版本化知识文件，运行校准与变形测试，发布固定配置。游戏内不需要每次选牌调用 AI 打分，分数与关键提醒立即可用。已有 AI 人格弹幕只负责采用角色口吻表达已确认事实；其请求节奏无需增加。
