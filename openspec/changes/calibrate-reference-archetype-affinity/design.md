## Context

用户最终目标是选牌教学：知道当前更靠近哪个流派，以及拿一张牌后为什么改变多少。2026-10-18 最新约束：不按来源版本筛选，只看卡牌。早期研究见 research/report.md；本次正式实现与复算见 research/results-v2.json 和 docs/archetype-affinity-calibration.md。旧原型仅为历史对照，不被产品引用。

## Goals / Non-Goals

**Goals:** 用真实牌表核对教学参照；按功能支持替代牌、连续配套、重复饱和、无关牌稀释；输出同一候选的真实前后差值与上下文原因；接入奖励、商店、桌面及游戏内选牌 overlay。

**Non-Goals:** 不预测胜率、不自动点击、不将契合度直接作为推荐排序。暂不增加其他角色或第五种流派，不改变怪物技能/人格弹幕节奏。

## Decisions

### 1. 实战参照与经典机制分别提供证据

攻略解释消耗、力量、格挡的机制，自动打击依据本地地狱狂徒与打击牌面。Spire Codex 对局提供完整实际牌表；网站相似度聚类只用于找候选，不直接充当专家标签。

四个方向有四份真实通关参照；消耗增加单抽牌、单格挡路线，共六条功能路线。完整牌表、来源 URL、需求量和标签在 agent/knowledge/archetype-references.js。参照自身满足声明需求并归一为 100，代表教学目标已满足，不代表它是唯一完美牌组。消耗参照含未知 Mod 卡，格挡参照含疯狂科学：它们的未知效果不参与功能加分，仍占牌组位置，保留不确定提示。

### 2. 各路线独立评分，取最贴近的一条

每个角色槽定义权重 w、需求 t、提供量 a；按 min(1,a/t) 连续计算覆盖 C。配合 L 是已声明的两端覆盖最小值的均值。密度 D 按卡牌提供的有效、未过量功能计算，每张牌最多一个信用单位；参考归一化得到 F。

```text
c_j = min(1, a_j / t_j)
C = Σ_j (w_j / 100) × c_j
L = mean(min(c_j,c_k))，对每条声明的配合边计算
S = 0.8 C + 0.2 L
u_i = Σ_j [g_ij / max(1,Σ_k g_ik)] × min(1,t_j/A_j)
D = Σ_i u_i / 牌组张数
F = min(1, D / D_reference)
契合度 = round(100 × S × F)
```

A_j 只含卡牌，遗物不挤占已有卡牌密度信用。各路线完整算后再择优，不能把甲路线的留存和乙路线的输出拼起来。可选功能允许零覆盖权重但有限密度信用；例如单抽牌消耗路线不要求无惧疼痛，但拿到它可提供额外功能，不当作无关牌。

参数是可解释的教学规则，不是统计最优拟合。缺启动只失去对应覆盖与配合，无 59/60 分截断或启动保底。未饱和组件可能有互补性：不能保证第二张牌在所有上下文中严格比第一张少加分；保证达到需求后不能无限靠副本刷分。

### 3. 牌面语义优先于名称与泛化字段

坚定不移放大格挡，壁垒保留格挡，两个功能不可混淆。劫掠是抽牌辅助，不能被地狱狂徒自动打出。契约终结的 Cards=3 是消耗堆门槛，其 cards_draw 字段不作真实抽牌。战鼓能量需外部消耗手段；撕裂需自伤来源。主宰自己施加易伤，不再要求先有另一张力量来源才计入。

升级按明确增加的抽牌、格挡、能量或力量修正，不统一乘 1.35。数值不完整时采用有限功能量；不声称模拟牌序、费用、检索、固有、消耗压缩或动态改造。

### 4. 选牌变化是教学主输出

before/after 都调用同一个评分器；deltaPoints 等于展示整数之差，同时记录 deltaExact。原因使用所选路线前后功能变化：补缺口、形成配合、资源支持、同类已充分、稀释或未知。零和负数如实显示；不会因为“这张是核心牌”保底加一。

旧 score/readiness 字段保留，均为同一个契合度数值。新增参考、置信度、标志性证据、前后功能快照和教学原因；Mod 可继续读取旧消息，新消息使用明确 before 快照，避免把候选当成已持有。推荐卡牌分数和排序不受影响。

### 5. 主副方向与运转状态分开

固定四方向顺序；先按整数契合度排序，最高低于 25 或没有标志性证据时方向不明确。副方向需至少 30 且达到首位的一半，最多两个；相差不超过 10 显示混合。桌面与 Mod 使用相同门槛与并列顺序。运转状态另看功能闭环，不覆盖契合度排序。普通资源/起手防御不构成强推关键启动牌的依据。

### 6. 校准可复算，不冒充独立评审

research/runs-v2.json 保留每方向五份完整牌表和三份额外混合反例，共 23 局。五份是来源组，包含参照来源，不能说成每方向五份独立验证。标签由当前 AI 依据机制核对，非独立专家；评分反馈后的标签澄清保留理由。每局对十五张候选重算四方向，共 1380 项差值检查。一个完美打击数量路线明确标为当前四方向未覆盖，不为让结果全通过而改称自动打击。

另外用删核心、同功能替代、重复、稀释、条件触发与未知输入做变形测试。结果保存事实与规则 SHA256，参数/规则变更后重新生成。来源版本不筛选、不乘分、不降低置信度。

### 7. AI 的边界

当前会话 AI 实际参与网页核对、机制归类、规则设计、反例分析及教学文案；没有额外调用独立模型或独立玩家评审，没有把提示文档当成执行日志。实时评分无网络或 API key 依赖。AI 可以解释已计算数值，不能改分、猜未知 Mod 效果或把通关直接当满分。

## Verification / Risks

- 用真实 Electron 页面与 preload/IPC 验证奖励和商店，保存截图；C# codec 消费同一个 JS 输出回放。
- Mac 本机的纯 C# 测试不等于游戏内 Godot overlay 实机验证，交付时明确区分。
- 每方向来源数量仍小，且参照偏好影响分数尺度；不宣称全套路覆盖或总体准确率。
- 大牌组的消耗压缩与未采集附魔未模拟，低分不能解释为牌组弱；完整模拟留待更多运行数据。

## 实测反馈修订

自动打击按打击输出40%、打击供给15%、抽牌循环18%、启动20%、通用资源5%、伤害放大2%分配。输出量区分普通打击、灰烬和完美打击；完美打击还需按当前打击数量提供有限成长信用。通用抽牌不能一张占15%，凶恶缺易伤源时不计收益，有源也只计有限条件支持。保持满分参照自洽、重复饱和和真实差值，不硬写某张牌固定加分。其余方向的通用资源比例也相应收紧，将释放权重留给本流派核心收益。

关键牌提醒按真实奖励机会保留，战斗退出快照/异步建议不构成机会关闭。只有确认选牌、关闭奖励、进入新场景等明确事件撤销。建议文本与关键牌提醒独立排队，重点关注不等于强制拿牌。

渲染回归还确认关键提醒携带内部reconfirm函数导致Electron IPC无法序列化。该函数只保留于主进程队列，出队消息必须为可结构化克隆的纯数据；用真实renderer/preload验证提醒与推荐分别上屏。
