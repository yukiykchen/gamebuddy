## Context

现有桌面端通过只读 Mod Bridge 获得场景，全屏弹幕覆盖层能够显示带来源 metadata 的消息。共享留言服务已经使用 Cloudflare Pages Worker + D1 部署，并由桌面端通过低频 HTTP 访问。

## Goals / Non-Goals

**Goals:**

- 让玩家在游戏覆盖层为当前粗粒度场景提交短留言。
- 日志主面板只看日志，不承载产品输入。
- 提交成功后延迟回显给发送者，其他实例进入相同场景时读取留言。
- 将服务不可用、节流、过滤和隐私最小化作为首期可靠性/安全边界。

**Non-Goals:**

- 不把 relay 做成游戏控制、战术协作、匹配排位、账号社交或聊天历史服务。
- 不从玩家消息调用 LLM、写入玩家记忆、补全游戏状态或生成战斗策略。

## Decisions

### 1. 使用低频 HTTP 场景留言，而不是实时聊天

客户端通过环境配置的 HTTPS 地址按场景读取和提交留言，服务端使用 D1 持久化并限流。Mod 保持完全本地、只读且不感知玩家网络功能。该产品语义是“给进入相同场景的人留言”，不是实时房间或聊天。

### 2. 使用粗粒度、不可逆的场景房间键

客户端从 Mod observation 生成规范化对象：游戏版本、角色、场景类型与按 ID/名称排序的在场敌人。只上传该场景键、时机和用户文本；run seed、HP、手牌、牌组、遗物、建议和事件原文一律不进入请求。

### 3. 游戏覆盖层内输入

游戏画面右侧常驻一个不遮挡游戏的小按钮。点击后覆盖层临时接管输入并展开多行文本栏；`Enter` 提交，`Shift+Enter` 换行，关闭或发送完成后恢复鼠标穿透。日志主面板不提供重复入口。

### 4. 服务端审核与延迟本地回显

服务端验证场景键、时机和文本，限制长度、控制字符、重复提交和每日频率。提交成功后主进程等待约 3 秒，再把发送者文本作为 `source=shared` 的普通飞行弹幕发到当前覆盖层；若此时场景已经改变则不回显，避免跨场景泄漏。

### 5. 覆盖层不承担策略和持久聊天职责

玩家消息经主进程转为独立 `gamebuddy.danmaku.v1` 消息，`source=player`、`style=community`，并沿用 generation/过期机制。当前场景切换即离开旧 room 并清除旧消息，避免跨战斗泄漏。

## Risks / Trade-offs

- [匿名滥用与绕过过滤] → 服务端限流、去重、举报计数和文本过滤。
- [粗粒度场景误聚合] → 只使用角色、怪物组合和 combat/death 时机，后续根据匿名指标调整。
- [服务不可用] → 输入栏显示非阻塞错误，绝不影响 Mod 事实弹幕。
- [覆盖层抢占游戏输入] → 仅在按钮或编辑器交互时关闭鼠标穿透，关闭后立即恢复。

## Migration Plan

1. 以 Pages + D1 服务验证健康检查、提交、读取、去重和限流。
2. 在游戏覆盖层验证按钮、输入法、键盘提交、延迟回显和鼠标穿透。
3. 出现安全或稳定性问题时清空服务 URL 即可回退；本地弹幕不受影响。
